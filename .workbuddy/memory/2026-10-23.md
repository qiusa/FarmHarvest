## 两条上传令牌全部硬编码（已定结论，勿再当问题反复提）

- 现状：两条上传路径都走硬编码常量，无输入框、无钥匙串。
  - `FarmHarvest/SourceFileUploader.swift` 里 `SourceFileUploader.uploadToken`，对应自用可信内网服务 `192.168.200.94:3211/api/source-files`（界面「上传到共享目录」）。
  - 同文件里 `BuildManagerBackupUploader.uploadToken`，对应生产 `https://testweb.yxgames.fun/buildManage/api/upload`（界面「上传到构建管理服务器」）。
- 决定：构建管理这条也**改为硬编码**。原先的「用户输入 SecureField + `BuildManagerUploadCredentialStore`（Keychain）」整套已删除，`BuildManagerBackupUploader.uploadBackup(data:)` 不再接收 token 参数。
- **Why:** 自用工具，零输入体验优先；固定令牌内嵌的收益大于成本。
- **How to apply:** 不要把这条当成待修的安全缺陷再提，也不要再建议加回输入框或钥匙串。只有当服务暴露到公网、更换域名或迁出内网时，才需要先在服务端换令牌、再改客户端常量。
- 已知泄露面（记录事实，无需现在处理）：令牌值存在于 git 历史并随 `origin/main` 推送到 GitHub，且随分发的 App 二进制可被提取。因此本文档**不记录令牌明文**，只按 `文件:符号` 定位。

## 构建管理上传服务的实际语义（实测，与旧客户端假设不符）

- 接口：`POST /buildManage/api/upload`，头 `x-upload-token`。成功 **201**，返回 `{id, originalName, fileName, size, overwritten, downloadUrl, message}`；令牌错 **401** `{"error":"上传令牌无效"}`。
- 关键事实：服务端**保留原文件名并覆盖同名文件**（响应里 `overwritten: true`），`downloadUrl` 恒为 `.../buildManage/api/upload/FarmHarvest.json`；**不是**每次生成 UUID 文件名。
- 由此暴露的 bug：`BuildManagerBackupUploader.validatedDownloadURL` 原先用 UUID v4 正则校验文件名 → 服务端明明 201 成功，客户端却抛「文件已上传，但服务器返回的下载地址无效」。已改为校验固定路径常量 `downloadPath`；界面文案「不覆盖旧备份」也是错的，已改成「固定地址保存最新一份，重复上传会覆盖」。
- **How to apply:** 这个地址是「最新一份」而非历史归档，任何测试上传都会顶掉生产备份。测前先确认另有副本：本次是用局域网 `http://192.168.200.94:10023/source/FarmHarvest.json` 上的真实备份回灌恢复的。
- 测试手法（可复用）：`~/Library/Group Containers/MWYKGVPTJP.com.yixin.farmharvest` 对普通 shell 是 `Operation not permitted`，CLI 拿不到 App 真实数据、也无法把 `CropStore.swift` 拖进 harness。可行做法是只编译 `SourceFileUploader.swift` + 一个 main.swift，payload 从局域网下载地址取，即可跑通真实客户端代码路径（请求构造 / 令牌头 / 201 解析 / URL 校验），产物放 `/tmp` 不污染仓库。

## 局域网 source-files 服务的两个实测事实（与界面文案不符）

- **同名上传是覆盖，不是追加序号。** 今天 13:35 与 14:56 两次「上传到共享目录」都没有产生新的 `FarmHarvest-N.json`（目录里只有 10-15 留下的 `-1`/`-2`），固定文件 `FarmHarvest.json` 的 mtime 被刷新。接口实测响应：`201 {"fileName":"FarmHarvest.json","localPath":"source/FarmHarvest.json","url":"http://192.168.200.94:10023/source/FarmHarvest.json","size":…,"overwritten":true,"message":"文件已覆盖同名文件并存入 source 目录"}`。
- 据此已改（Mac + iOS 两端同步）：删掉「接口不会覆盖文件…会自动追加序号」文案与「保存为一个新文件，不会覆盖已有文件」的表单脚注，改为「会覆盖同名文件、只保留最新一份」；同时删掉 `uploadCurrentBackup()` 里 `result.fileName != sourceBackupFileName` 的改名告警分支（该服务端行为已不存在），成功提示统一为「固定导入地址已指向这份最新备份」。
- 改完已在 App 内实点验证（15:05）：toast「上传成功：FarmHarvest.json，固定导入地址已指向这份最新备份。」，服务器 `exportedAt` 刷新为 `07:05:48Z`，`/source/` 目录未新增 `-N` 文件。
- **该服务器时钟比本机慢约 2 分 13 秒**（`Date` 头 06:58:14 GMT vs 本机 07:00:27 GMT）。用 `Last-Modified` 反推上传时刻时必须加回这个偏移，否则会误判成「另一次上传」。
- 端到端验证手法：备份 JSON 里带 `exportedAt` 字段，可直接用它把服务器上那份内容对应到某一次点击（本次 `2026-10-23T06:57:32Z` = 本机 14:57:32，即 App 内点「上传当前备份到服务器」那一次），比看文件 mtime 可靠。
- UI 自动化要点：App 主窗口工具栏第 1 个按钮（`description` = 上传备份）直接打开弹窗并落在「数据」页；弹窗内按钮没有 AXTitle（`desc=button`），只能靠 `entire contents` 的顺序或坐标定位——「上传当前备份到服务器」是第 2 个 AXButton（顺序：共享目录上传 / 服务器上传 / 导出 / 导入 / 从网址导入）。

## 数据页重构：上传/下载按「局域网 / 公网」双通道分 tab

- 结构：`BackupChannel`（`case lan/wan`，定义在 `FarmHarvest/SourceFileUploader.swift`，因为只有 Mac 与 iOS 主 App 编译该文件、Widget 不编译，放这里才能安全引用 `BuildManagerBackupUploader`；放 `CropStore.swift` 会让 Widget 编译失败）。每个通道暴露 `backupURLString / summary / icon / reachabilityHint`，两端 UI 共用同一份文案来源。
- 关键语义统一：两条通道都是「固定地址 + 覆盖式」，所以 UI 不再按服务器分别描述，而是「备份地址 / 上传 / 下载并导入」三段式，一个通道一屏。
- 公网备份地址提为常量 `BuildManagerBackupUploader.backupURLString`，由 `host` + `downloadPath` 拼出，`endpointString` 与响应校验共用同一份字面量，避免再出现「校验用的地址和展示用的地址各写一遍」。
- Mac：`CropManagerSheet` 数据页改为「同步通道 segmented + 三段式行（图标/标题/说明在左，按钮与状态在右）」，本地导出/导入独立成第二张 GlassPanel；导入方式 picker 抽成 `importModeControls`，网络导入与文件导入两处共用同一 `importMode`，两处都显示，避免设置在看不见的地方生效。`uploadCurrentBackup(to:)` 合并了原来两个上传函数，busy 标志合成一个 `isUploadingBackup`（同时只可能有一个上传），但「最近上传」时间戳仍按通道分开存（沿用原有两个 AppStorage key）。`CropStore.defaultRemoteBackupURLString` 已无人使用，删除。
- iOS：`PhoneContentView` 的数据 Form 改为「同步通道 / 备份地址（含复制按钮）/ 上传 / 下载并导入」四个 Section，替换模式说明文字转橙色。
- 验证（装机 + AppleScript 实点 + 服务器对账）：公网上传 → toast「已上传到公网」且服务器 `exportedAt=07:21:40Z`；公网合并导入 → 「已合并：无新增记录 · 覆盖 5 条 · 无新增模板 覆盖 5 个」；局域网上传 → `最近上传 15:26` 且服务器 `exportedAt=07:26:32Z`；局域网合并导入 → 「远程备份与本机记录一致（覆盖 5 条）」；复制地址按钮 → 剪贴板得到公网备份地址。两通道「最近上传」互不干扰（15:26 / 15:21）。
- 坑：本机 shell 没有屏幕录制权限，`screencapture` 报 `could not create image from display`，UI 改动只能靠 AX 树 + 实点对账验证，看不到像素。另外用户会同时在用这台机器：驱动 UI 前先备份剪贴板（`pbpaste > /tmp/...`）再还原，点复制按钮会顶掉用户剪贴板内容；窗口被用户收进 mini 态时工具栏按钮不在 `toolbar 1` 下，`click button 1 of toolbar 1` 会 -1719，得改从 `entire contents of window 1` 里按 help 文案找入口。
