## 修复「种下并记录」点击无反应（重要教训）

### 根因（两层叠加）
1. **直接原因**：App Group 容器目录 `~/Library/Group Containers/MWYKGVPTJP.com.yixin.farmharvest` 能拿到路径（containerURL 非 nil），但**目录不可写** —— 该目录是旧安装残留、由别的签名身份创建，adhoc 签名的新 App 没有写权限。原代码 `containerURL?.appendingPathComponent` 得到 nil → 所有 `guard let ... else { return }` 静默失败 → 点了没反应。
2. **放大器**：我之前手动 `codesign --force --deep --sign -` 把 Xcode 签好的 entitlements（app-sandbox + application-groups）冲掉了。**教训：安装时绝不要手动 codesign --force，直接用 xcodebuild 产物，它已带正确 entitlements。**

### 修复内容（CropStore.swift / ContentView.swift）
- `storageRoot` 从可选链改为**非可选 static let**：容器通过**真实写探测**（写临时文件再删）才使用，否则退回沙盒 `Application Support/FarmHarvest`。新增 `isWritable(_:)` helper。
- `isSharedContainerAvailable` 同样改为「拿到路径 **且** 可写」，不再只看 containerURL != nil。
- `save()` / `saveCustom()` 用 do-catch 替代 `try?`，失败走 `diag()`（os_log）。
- ContentView 新增 `saveFailed` 状态：新增后重新 load 校验记录数，未增加则红色提示「保存失败」。
- ContentView 启动时调`CropStore.diagnoseEnvironment()`，把存储根/容器可用性/读写探测结果显示在界面灰框里（textSelection 可复制）。

### 我引入并修掉的 bug（务必记住）
- **static 初始化重入崩溃**：最初在 `storageRoot` 的初始化闭包里调了 `diag()`，而 `diag()` 又访问 `storageRoot` → `_dispatch_once` 重入 → 无限递归 → SIGTRAP，App 启动即崩（窗口数 0）。定位方式：读 `~/Library/Logs/DiagnosticReports/*.ips` 栈帧，看到 `CropStore.storageRoot.unsafeMutableAddressor` 与 `specialized static CropStore.diag` 交替。**规则：static let 的初始化闭包里绝不能调依赖它自己的函数。**

### 环境限制（非代码问题）
- 本机 TCC 极严：`~/Library/Containers/com.yixin.farmharvest/**` 与 `~/Library/Group Containers/**` 从外部 `stat` 可以（拿到路径/大小/mtime），但 `open()/read()` 一律 PermissionError。所以验证写盘只能看 stat 是否生成 + 界面是否刷新，**不能靠读文件内容**。
- os_log 在 Release 下抓不到（`log show` 查不到），因此诊断信息直接渲染到界面上。
- GUI 自动化（AppleScript click at / CGEvent）在此多显示器环境不可靠：会把窗口拖动导致窗口丢失，或点偏。有效做法：先 `set position of window 1` 固定窗口 → screencapture -R 截图 → 用 PIL 按像素找蓝色按钮算全局逻辑坐标（注意截图是 2× Retina，坐标需 ÷2 + 窗口偏移）。

### GUI 自动化踩坑（累计）
- 本环境 screencapture 的预览图会被等比缩放，**不能拿预览图上的视觉坐标直接算点击位置**；必须用 PIL 在原始 PNG 上扫描像素。
- 窗口 `set size` 会被 SwiftUI minWidth/minHeight 约束（设 1080 实际只给 892）。
- 终端窗口会抢走点击焦点，测试前要先隐藏终端。
- Tab 遍历焦点在多个 TextField 间循环，到不了记录行的按钮。
- AppleScript `every button of window` 对 SwiftUI 控件返回 `missing value`，拿不到标签。
- 结论：本项目 GUI 自动化验证效率极低，优先用「构建通过 + 代码逻辑核对 + 观察落盘/界面状态」验证。
